### Issue 500: fix(stackctl): make sync fail closed when generation fails or stack output is missing

**Status**: VERIFIED ACCURATE

**Findings**:
- `stackctl.sh:470` -- `python3 "$SCRIPT_DIR/tools/generate_stacks.py" --output-dir "$tmp_dir" 2>/dev/null || true`
  - `|| true` suppresses generator exit code
  - `2>/dev/null` discards stderr
- `stackctl.sh:476-479` -- when generated file is missing, logs "Warning" and `continue`s instead of marking drift
- `stackctl.sh:505` -- can still print "All stacks are in sync" after generator failure
- CI at `.github/workflows/ci.yml:61` correctly calls `generate_stacks.py` without `|| true` (confirms CI treats drift as blocking)
- `cmd_sync()` has no `--stacks` filtering so it always checks all 3 stacks

**Risk**: MEDIUM -- false confidence before deployment
**Implementation scope**: Single function `cmd_sync()` in `stackctl.sh`
**Branch**: `fix/stackctl-sync-fail-closed`

### Issue 501: fix(stackctl): align shell syntax with supported Bash version contract

**Status**: VERIFIED ACCURATE (and confirmed broken on macOS)

**Findings**:
- `stackctl.sh:1054` -- `local -A dir_to_stack=()` -- Bash 4+ associative array
- `stackctl.sh:912` -- `local -a all_dirs=()` -- standard indexed array (OK everywhere)
- macOS system bash: **3.2.57** (confirmed via `bash --version`)
- Script shebang: `#!/usr/bin/env bash` which resolves to 3.2.57 on macOS
- `project-stackctl-changes` skill explicitly states: "Prefer POSIX-safe or guarded shell features so the script keeps working on macOS"
- This will produce a **syntax error** on macOS, not a graceful error

**Risk**: HIGH -- script is broken on macOS (all commands that enter `cmd_secrets` → `_secrets_deploy` path)
**Implementation scope**: Replace associative array in `_secrets_deploy()` with standard array + linear scan
**Branch**: `fix/stackctl-bash-portability`

### Issue 503: fix(observability): validate APISIX Prometheus scrape target after Swarm service renaming

**Status**: VERIFIED ACCURATE

**Findings**:
- `prometheus.yml:48` -- target is `apisix-gateway:9091` (hyphen)
- `apisix/api-gateway/docker-compose.yml:11` -- service key is `apisix_gateway` (underscore)
- `apisix/api-gateway/docker-compose.yml:12` -- `container_name: "apisix-gateway"` (hyphen, gets stripped)
- `stacks/infrastructure.yml:56` -- generated service is `apisix_gateway` (underscore)
- Swarm DNS: `<stack>_<service>` = `infrastructure_apisix_gateway`
- No network alias for `apisix-gateway` exists in the config

**Risk**: MEDIUM-HIGH -- Prometheus scrape will fail silently if this doesn't resolve
**Implementation scope**: Update `prometheus.yml` target, document Swarm DNS convention
**Options**:
  A. Change target to `apisix_gateway:9091` (short service name, works within same stack)
  B. Change target to `infrastructure_apisix_gateway:9091` (fully qualified)
  C. Add network alias `apisix-gateway` to the APISIX service (preserves target)

**RECOMMEND**: Option A (short service name) since Prometheus is in the same Swarm and they share the `traefik-public` network. Short service names resolve within a stack.
**Branch**: `fix/prometheus-apisix-scrape-target`

### Issue 504: chore(mongo): validate overlapping mongo-data volume mounts

**Status**: VERIFIED ACCURATE (ambiguous, needs clarification)

**Findings**:
- `mongo/docker-compose.yaml:19-21` -- same `mongo-data` volume mounted at `/data`, `/data/db`, `/data/configdb`
- `/data/db` is the default MongoDB `storage.dbPath`
- `/data/configdb` is MongoDB's config DB path
- Both are subdirectories of `/data`
- Docker volume mount semantics with same volume at nested paths is implementation-defined

**Risk**: LOW -- not proven data loss, but ambiguity in backup/restore semantics
**Implementation scope**: Reduce to one mount (`/data`) or document intent
**Options**:
  A. Keep only `/data` mount (default MongoDB paths `/data/db` and `/data/configdb` are subdirectories)
  B. Separate volumes: `mongo-data` for `/data/db`, `mongo-config` for `/data/configdb`
  C. Document existing behavior and leave as-is

**RECOMMEND**: Option A -- single `/data` mount. The nested mounts are redundant since `/data/db` and `/data/configdb` are subdirectories of `/data`. This is the simplest and most maintainable.
**Branch**: `chore/mongo-volume-validation`

### Issue 505: feat(stackctl): support gitignored partial stack overrides for local and dev-server deployments

**Status**: VERIFIED ACCURATE (valid feature request, not a bug)

**Findings**:
- No existing override mechanism in `stackctl.sh`
- `cmd_up()` has no `--override` or `--profile` flags
- `.rendered/` is gitignored but not designed for user-provided overrides
- Docker supports multi-file Compose merging (`docker compose -f base.yml -f override.yml config`)
- This is a non-trivial feature spanning generator, renderer, and deploy paths

**Risk**: N/A (feature)
**Scope**: BROAD -- affects `stackctl.sh`, `tools/render_compose.py`, `tools/generate_stacks.py`, docs
**Implementation complexity**: HIGH
**Note**: This is the largest issue. Should be implemented last or possibly in a separate session.

**Branch**: `feat/stackctl-overrides`
